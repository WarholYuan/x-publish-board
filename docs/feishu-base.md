# 飞书 Base「X 运营」建表手册

整套系统的唯一数据源。先建 Base，再建四张表，最后建仪表盘。字段名一个字都不要改——渲染与回采代码按字段名读写，改名即断链。

机器可读的完整定义在 `feishu/schema.json`，半自动建表脚本在 `feishu/create_base.sh`（基于 lark-cli，公式字段与 lookup 字段脚本会给出提示，个别需在飞书界面确认）。

## 表 1：发布库（核心表，32 字段）

| # | 字段 | 类型 | 说明 |
|---|---|---|---|
| 1 | 标题/首句 | 文本（主字段） | 长文是标题；短帖只是内部标识，不发出去 |
| 2 | 正文 | 文本（多行） | 要发出去的全文 |
| 3 | 图片 | 附件 | 最多用前 4 张上板，源附件不限 |
| 4 | 状态 | 单选 | 待发布 / 已上板 / 已发布 / 已复盘 |
| 5 | 板上编号 | 文本 | 渲染时自动生成 `x-` + record_id 哈希前 8 位并回写，不用手填 |
| 6 | 账号 | 单选 | 你的发布账号，如 @your_handle（可多个） |
| 7 | 计划发布时间 | 日期时间 | `yyyy-MM-dd HH:mm` |
| 8 | 发布时间 | 日期时间 | 点「发完了」时由状态服务自动写 |
| 9 | 帖子链接 | 超链接 | 发完贴回；为空时回采会尝试自动匹配 |
| 10 | 串/首条回复 | 文本（多行） | 线程的后续条 / 首条回复 |
| 11 | 内容类型 | 单选 | 长文 / 短帖 / 线程 / 图帖 / 视频 / 转帖+观点 |
| 12 | 打法类型 | 单选 | 自己开局 / 蹭局 / 组局 / 日常互动 |
| 13 | 选题来源 | 关联 | 双向关联到「选题池」，反向字段自动生成 |
| 14 | 是否商单 | 复选框 | |
| 15 | 发布时粉丝数 | 数字 | 精度 0 |
| 16 | 1小时互动 | 数字 | 1h 窗口回填 |
| 17 | 24小时曝光 | 数字 | 24h 窗口的曝光快照（后加字段，回采要用） |
| 18 | 曝光 | 数字 | 最新 / 72h 定格曝光 |
| 19 | 点赞 | 数字 | |
| 20 | 收藏 | 数字 | |
| 21 | 转发 | 数字 | |
| 22 | 回复 | 数字 | |
| 23 | 主页访问 | 数字 | 仅扩展从 Analytics 能拿到 |
| 24 | 链接点击 | 数字 | 仅扩展从 Analytics 能拿到 |
| 25 | 本帖涨粉 | 数字 | |
| 26 | 互动率 | 公式 | 见下方 |
| 27 | 收藏率 | 公式 | 见下方 |
| 28 | 千次曝光涨粉 | 公式 | 见下方 |
| 29 | 爆文判定 | 公式 | 见下方 |
| 30 | 收入/线索 | 数字 | 精度 2；金额与线索数共用一列，所以不用货币格式 |
| 31 | 复盘归因 | 文本 | |
| 32 | 可复用点 | 文本 | |

公式（原样填，输出是小数比率，前端可显示为百分比）：

```
互动率       = IFERROR(IF([曝光]>0,(IFBLANK([点赞],0)+IFBLANK([收藏],0)+IFBLANK([转发],0)+IFBLANK([回复],0))/[曝光],0),0)
收藏率       = IFERROR(IF([曝光]>0,IFBLANK([收藏],0)/[曝光],0),0)
千次曝光涨粉 = IFERROR(IF([曝光]>0,IFBLANK([本帖涨粉],0)/[曝光]*1000,0),0)
爆文判定     = IFERROR(IF(AND([曝光]>=100000,[曝光]>=IFBLANK([发布时粉丝数],0)*5),"爆文",""),"")
```

## 表 2：选题池（10 字段）

| # | 字段 | 类型 | 说明 |
|---|---|---|---|
| 1 | 选题标题 | 文本（主字段） | |
| 2 | 选题来源 | 单选 | 当日热点 / 社区热议 / 对标账号 / 自有产品动态 / 常青干货 / 评论区问题 / 大V帖衍生 |
| 3 | 来源链接 | 超链接 | |
| 4 | 预期内容类型 | 单选 | 同发布库的六种内容类型 |
| 5 | 预期打法 | 单选 | 同发布库的四种打法 |
| 6 | 痛点时效 | 单选 | 当日热点 / 本周热点 / 常青 |
| 7 | 状态 | 单选 | 待写 / 已写待发 / 已发布 / 弃用 |
| 8 | 关联发布记录 | 关联 | 表 1「选题来源」的反向字段，建关联时自动生成，不要再建第二对 |
| 9 | 实际曝光 | 汇总（lookup） | 对关联发布记录的「曝光」求和：lookup + aggregate=sum |
| 10 | 命中备注 | 文本 | |

用法：X 书签当随手收集箱，真正要写的选题落到这里；写完转发布库并关联，曝光会自动汇总回来，看哪类选题真的出量。

| 4 | 认证粉丝数 | 数字 |
| 5 | 当日总曝光 | 数字 |
| 6 | 当日涨粉 | 数字 |

## 表 4：对标账号（7 字段）

| # | 字段 | 类型 |
|---|---|---|
| 1 | 账号 | 文本（主字段，如 @someone） |
| 2 | 类别 | 单选（按你的赛道自定，如 私域打法 / 私域方法 / 小红书运营） |
| 3 | 粉丝数 | 数字 |
| 4 | 主页 | 超链接 |
| 5 | 对标点 | 文本（学他什么：钩子、引流路径、选题……） |

纯手工维护的参考表，不参与自动化，字段可按需增减。

## 仪表盘「数据看板」（9 块，可选但推荐）

- 数字卡 ×3：最新粉丝总数、认证粉丝数、近3个月总曝光（都取账号日快照；飞书聚合没有「按最新日期取一条」，用 MAX 近似，粉丝单调增长时等价）；
- 折线图 ×1：账号日快照按日期的当日总曝光趋势；
- 柱状图 ×3：发布库按选题来源的发布数、爆文数；按内容类型的平均曝光；
- 排行榜 ×1：发布库按互动率 TOP 10 帖子；
- 文本标题块 ×1。

飞书图表不支持中位数，需要时用平均曝光代替，或另建辅助计算。

## 建完之后

把 Base token 与四张表的 table_id 填进 `config.env`（`lark-cli base +table-list --base-token <token> --as user` 可查 ID）。在发布库放一条 TEST 记录（随便填曝光等数字），部署完渲染后应出现在板上，公式应自动算出互动率。
